What this is

serve git is a small, local web interface for the repository this command was started in. It is a thin front-end over the system git binary: every button runs a real git command, and the command bar at the bottom of the page shows exactly which one. There is no database, no background state and no bundled copy of your history.

Repository: {{ROOT}}

The page talks to a JSON API on the same port; the API is for this UI and is not a stable public interface.

Quick start

  1. Run ntc serve git [path] from the repository (or pass its path), optionally with --port / --bind.
  2. Open http://127.0.0.1:8091.
  3. In Changes, tick the files you want and press Stage selected.
  4. Write a message in the sticky footer and press Commit staged (Ctrl+Enter).
  5. In Remotes, Fetch, then Pull, Push or Publish branch.

Default port and bind can be changed permanently with serve config git --port-default N --bind-default ADDR (alias config serve git).

Tabs

The left rail is the whole page. Each tab has its own hash route, so a link like #/changes/file/src%2Fmain.rs or #/history/<hash> survives a reload and can be bookmarked.

Repository
Repository facts (root, HEAD, upstream, ahead/behind, remotes, working-tree state) plus quick actions: refresh, fetch, open Changes/History, create a branch.
Changes
Every changed file with its index/worktree state, filterable by path and by staged/unstaged/untracked/conflicts. Stage, unstage or discard the selection, or use the per-row buttons. The diff of the selected file opens in the inspector; the commit box is a sticky footer.
History
The last 30 commits. Click one to list the files it changed, with the commit hash ready to copy.
Branches
Local branches: switch, create and switch, rename, safely delete (git branch -d), merge the selected branch into the current one, or rebase the current branch onto it.
Remotes
Pick a remote, fetch it, preview incoming commits, publish a branch that has no upstream, push, or pull with --ff-only.
Stash
Stash tracked changes with an optional message, then apply, pop or drop an entry.
Tags
List, create (lightweight or annotated) and delete local tags, and push every tag to a remote.
Actions
Merge/rebase state, Continue rebase, and the conflict resolver: take Ours or Theirs for a whole file, or edit it yourself and press Resolved.

Keyboard

  • 1–8 switch tab (ignored while typing).
  • / focuses the current tab's filter.
  • j/k or ↑/↓ move through the file list, Space toggles the current file.
  • Ctrl+A in Changes selects every file in the current filter; Shift-click selects a range.
  • Ctrl+Enter in the commit message commits the staged changes.
  • R reloads the active tab, Esc closes the inspector.

Rules and safety

  • Local by default. The server binds 127.0.0.1:8091. Anyone who can reach the bind address can run git operations on this repository with your permissions, and there is no authentication — only use --bind on a network you trust.
  • Real git only. Actions shell out to git and report git's own errors; the echoed command is the command that ran.
  • Paths are checked. Stage, unstage and discard accept only paths that git status reports as changed. Discard keeps staged changes and refuses untracked files, conflicted paths and files with nothing unstaged.
  • Names are checked. Branch and tag names must be valid ref names and are matched against the existing local branches/tags before use. Deleting a branch uses git branch -d, so unmerged branches and the current branch are refused.
  • Remote actions need context. Push and pull require a checked-out branch with an upstream; Publish sets one with git push -u <remote> <branch>. Pull is --ff-only, so it never creates an unresolved merge commit.
  • No credential prompts. Fetch, push, pull, publish and tag pushes disable interactive prompts, so missing credentials fail with git's error instead of hanging the server. Configure SSH keys or a credential helper first.
  • Bounded output. Diffs stop at about 200 KB, commit file lists at 500 entries, commit and incoming lists at 30 entries, and commit messages at 4096 characters. Untracked files are not stashed.

If something goes wrong

  • A merge conflict keeps MERGE_HEAD until you commit the merge from the Changes tab; resolve every file in Actions first.
  • A rebase conflict leaves the rebase unfinished until Continue rebase in Actions; committing is disabled meanwhile.
  • If the page seems stale, press Refresh (R) or turn on Auto. Status is cached for about two seconds; actions that validate paths re-read it.
  • Anything the UI cannot do is still available in your terminal — the echoed command is a good starting point.

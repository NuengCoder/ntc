02 · Execution model

How a line becomes an action.

NTC is not a wrapper that shells out for everything. It dispatches its own commands, expands aliases and teleports, then sends the rest to the platform shell.

Step 01

Read the line

The shell tokenises input, completes commands and hints, and keeps history and autosuggest in the loop.

history · autosuggest · hints
Step 02

Expand shortcuts

Aliases expand into parameterised commands. @tp paths resolve before filesystem work. Local config overlays global aliases.

ral → @teleport → local overlay
Step 03

Dispatch

The command registry claims NTC builtins. Unknown commands pass through to the system shell with the same pipes and redirects.

execute_command · native fallback
Step 04

Produce output

Results return as terminal text, trees, tables, TUIs, generated files, reports, HTTP responses or served web apps.

text · TUI · file · report · web
Step 05

Pipe or persist

Text output can feed gs, sort, head, tail, betw, encode, qur or be redirected to disk.

a | b · > · >> · < · << · <<<
Step 06

Reuse the result

Aliases, ran targets, scr scripts, watcher triggers and the editor terminal can call the same commands again.

ral · ran · scr · watch trigger · ne

Dispatch rule

src/shell/commands/mod.rs

NTC owns the command name if it exists in its registry. Otherwise the line is treated as a system command. That is why git status, dir, ping and native tools work beside builtins.

Pipes and redirects are parsed by the NTC shell, so view | gs main does not require a second shell process.

Resolution order

what wins
  • 01Local project config overlays aliases, hints, ignore/care, fake groups and DB aliases.
  • 02Global config supplies every other setting. It remains the base layer.
  • 03Teleports are global only, even when a local config exists.
  • 04System commands are the final fallback when NTC has no matching builtin.
03 · Workflows

How features work together.

NTC’s value is not a list of commands. It is the hand-offs: shortcuts call navigation, navigation feeds views, views feed search, and search feeds reports and scripts.

Navigation

Create a jump point, then inspect it

Save a directory as a global teleport. Later, resolve it directly inside view, size, report, copy/move, or editor commands.

tp add web→@web→view @web/ -d 2→size @web --care
tp add web C:\code\web && view @web/ -d 2 -t
Automation

Turn a repeatable task into one word

Parameterised aliases can call other aliases, builtins and system commands. Share them as .ntc.ral files or keep them local to a project.

ral add ship(x)→cargo build→ran deploy $x→ship prod
ral add ship(x) "cargo build --release && ran deploy $x"
Reporting

Turn a directory into a deliverable

Inspect the tree, filter what matters with ignore/care, then export text, JSON, Markdown, HTML, PDF, DOCX or XLSX. The HTML report has its own theme toggle.

ignore dir→view→report html→--cp
ignore dir node_modules && report html --cp
Search

Keep only the files worth searching

ignore and care are shared by tree views, size, search, scans and line totals. One policy shapes every file-aware command.

ignore ext .log→gs TODO→qur→gs | head
ignore ext .log && gs TODO | head 20
Web

Serve the workspace or play a game

serve files exposes the current directory through the embedded file-drive UI. serve chess starts the embedded chess app. Both support LAN sharing.

serve files→ntc_web→--port→--share
serve files --port 8080 --share
Editor

Edit, run, and diff without leaving NTC

The built-in editor carries an NFE sidebar, git diff, teleport jumps and an embedded NTC shell. nerun.toml maps file types to run commands.

ne file→:tp→NFE→nerun→git diff

The mental model

read this first

Navigation answers “where am I going?”. Toolkit answers “what do I do there?”. Center is the shared state that makes both fast: aliases, teleports, config, ignore rules, history and the watcher.

Most commands are standalone, but the leverage comes from composition. A teleport is useful in view, but it is also accepted by size, report, cp, mv, txtf and the editor.

Two kinds of “integration”

internal vs external

Internal integration means a feature is genuinely wired into NTC: shared path resolver, config loader, ignore policy, command registry, or embedded UI.

External integration means NTC drives a native tool or service: git, PowerShell/cmd, HTTP APIs, SMTP, SSH, OpenWeather, or the OS clipboard.

Config precedence

highest wins
  • 1Project ntconfig.toml — local aliases, hints, ignore/care, fake groups, DB aliases.
  • 2Global config.toml — base behavior and every global setting.
  • 3Built-in defaults — used when neither file defines a value.
  • ×Teleports do not participate. They are global even inside a local project.

Project initialization

init / local

init --ran creates a task runner file. init --local creates a local config. init --opencode adds project-level opencode configuration.

local init creates a commented ntconfig.toml template; local deinit removes it. Use showcg and opencg for the global side.

06 · Boundaries

What not to assume.

NTC is broad, but it is not magic. These are the practical limits that change how you chain commands or choose a platform.

TUIs are not pipeable

ne, sys, nms play, nsheet and ndb take over the terminal. Do not expect useful output from piping them into gs or redirecting them to a file.

Windows-only features

usrpath, syspath, autoup and mode are Windows-specific. The README describes the current release as Windows-only, although the source contains Linux and Android build paths.

Android trims some formats

PDF, DOCX, XLSX and clipboard-dependent paths are not available in every Android build. Check the command’s help output rather than assuming desktop parity.

Two separate themes

The terminal theme (nice.ntc_theme and friends) does not style the generated HTML report. The report ships its own light/dark toggle.

Aliases are shell-level

Aliases run inside the NTC shell. Calling ntc myalias from another terminal is a different invocation than typing myalias in the interactive shell.

External services need setup

Weather needs an OpenWeather key, SMTP needs credentials, SSH needs profiles or keys. Network commands can fail for the same reasons any client would.

Reports reflect ignore policy

ignore/care affects what reports and file-aware commands include. If a report looks wrong, inspect igcared before changing the report command.

No universal undo

backup has its own restore/undo model and tpb undoes teleports, but file deletion, config edits and remote operations are not covered by one global undo stack.
